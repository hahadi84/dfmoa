# 내부 인기검색 기반 가격 갱신

- GitHub Actions `snapshot.yml`: 매일 07:00 KST에 시작하도록 예약한다. GitHub 스케줄은 실행 대기 때문에 지연될 수 있고 수집·배포 완료는 시작 이후다.
- 검색 화면에서 등록 상품과 정확히 매칭되는 검색어만 익명 집계한다. 브랜드·광범위 검색 및 미등록 상품은 순위에 반영하지 않는다.
- 브라우저 탭의 임시 UUID를 사용해 같은 상품·같은 한국 날짜는 한 번 집계한다. 원문 검색어, UUID, IP 주소는 저장하지 않는다. 순위는 사람 수가 아니라 최근 7일의 상품별 탭·일 검색 수다. Do Not Track 요청은 제외한다.
- Netlify Blobs의 불변 이벤트 키를 사용하므로 동시 요청이 공용 카운터를 덮어쓰지 않는다. 배포 미리보기는 deploy store로 격리한다.
- `prune-search-demand`는 매일 06:45 KST에 7일 범위 밖 이벤트를 삭제한다. 예약 함수는 운영 배포에서만 실행된다.
- `/api/search-demand` GET은 등록 상품 slug와 집계 수만 반환한다. 개인 식별 정보나 검색 원문을 반환하지 않는다.
- 오전 수집 작업은 집계 API를 읽어 최대 30개 인기 상품부터 수집하고 기존 카테고리 목록으로 40개를 보완한다. 인기 수집 실패는 다른 상품 재수집을 막지 않는다.
- 집계 API 장애 또는 배포 전에는 고정 카테고리 목록을 수집하고 홈은 추천 검색어로 표시한다. 저장 집계가 48시간 넘으면 인기순에 쓰지 않는다.
- 홈 가격 카드는 최근 3일 안에 확인된 가격 중 인기 상품 우선으로 표시한다. 인기 상품의 가격이 없으면 최근 가격 목록을 제공한다.
- 일시적 네트워크 수집 실패는 이전 정상 가격과 확인 시각을 유지한다. 매칭 실패·접근 정책 제한은 이전 후보를 재사용하지 않는다. 가격 이력에는 당일 새 수집 결과만 기록한다.
- `data/search-demand.json`, 가격·가격 이력의 Git 변경을 커밋한 뒤 기존 Netlify Git 배포 또는 build hook을 사용한다.

## 운영 연결 확인

2026-10-15 확인: 운영 Netlify 프로젝트에는 Git 저장소가 연결되지 않았고 이전 CLI 배포만 게시되어 있었다. GitHub main의 가격 스냅샷은 갱신되고 있었으나 공개 사이트는 2026-06-14 가격을 노출했다. PR #1을 main에 병합했고 `hahadi84/dfmoa` main에서 빌드하도록 연결한다.

운영 사이트에만 있던 10개 페이지는 배포 전에 `data/preserved-pages.json`으로 공개 본문을 보존했다. `/methodology`, `/price-compare` 및 4~6월 리포트·월간 혜택의 기존 URL과 제목을 유지한다. 스크립트·이벤트 핸들러·검색 이외 폼은 보존 본문에서 제거했고 기존 공통 레이아웃으로 렌더링한다. 이 자료는 원본 TypeScript 소스의 복구가 아니라 발행된 편집 콘텐츠의 보존본이며, 향후 수정은 해당 데이터나 별도 원본 모델로 이관한다.
