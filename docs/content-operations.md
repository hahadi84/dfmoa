# DFMOA 콘텐츠 운영

## 발행과 갱신
- 기존 GitHub Actions `snapshot.yml`이 매일 07:00 KST 실행될 때 `scripts/content-refresh.mjs`를 실행한다. 예약 실행은 GitHub 사정에 따라 지연될 수 있다.
- 현대면세점 공개 행사 목록의 행사명과 명시적 시작일/종료일을 확인해 당일 유효한 행사만 최대 6개 수록한다. 별도 자격 검토가 필요한 카드 발급 캐시백은 제외한다. 이는 행사 상세 조건 검증이나 모든 면세점 전체 혜택 목록이 아니다.
- 월간: 매월 첫 성공 수집 때 새 호를 만들고, 같은 달에는 행사 변경 시 갱신한다. 최초 발행일과 이전 월 기록은 보존한다.
- 주간: 한국 시간 월요일부터 새 주로 본다. 첫 성공 수집에 한 번 발행하며, 해당 주 재실행은 새 호를 만들지 않는다. 이전 호의 내용은 수정하지 않는다.
- 수집 실패·기간 추출 실패 시 새 보고서를 만들지 않는다. 이전 정상 자료를 보존하고 작업을 실패로 표시한다. 지난 자료의 확인일을 오늘로 바꾸지 않는다.
- ECB 기반 JPY/KRW 참고 환율을 Frankfurter에서 매일 수집한다. 7일 이상 오래된 응답·잘못된 통화·비정상 숫자는 거부한다. 공개 페이지에는 실제 기준일과 참고 환율임을 표시한다.
- 일일 수집 결과는 `[skip netlify]` 커밋으로 기록하고 build hook을 호출하지 않는다. 운영 공개는 아래 월요일 정기 점검 때만 한다. RSS·사이트맵도 해당 정기 배포 때 반영된다.
- 이메일 발송은 이 작업 범위에 포함하지 않는다. 사이트와 RSS에 발행한다.

## 주 1회 공개 정책 (2026-10-27 사용자 요청)

- 2026-10-29 사용자 직접 요청으로 당일 1회 예외 공개를 승인했다. `release(requested): 2026-10-29`만 해당 한국 날짜에 허용하고 기존 이력·중복·운영 환경 검사를 유지한다. 이후 월요일 정기 공개 정책은 계속 적용한다.

- 매일 데이터 수집은 유지하고, 소스·미리보기·운영 배포를 평일에 생성하지 않는다. 변경은 로컬에서 검증하거나 `[skip netlify]`로 저장한다.
- 기존 월요일 09:00 KST 점검 자동화가 주간 공개를 담당한다. GitHub에 별도의 주간 배포 예약을 추가하지 않아 중복 공개를 피한다.
- 다음 정기 공개일은 2026-11-02다. 정확한 시각은 실행 환경에 따라 지연될 수 있다.
- 정기 실행 전에 원격 최신 상태를 가져오고 로컬 사용자 변경을 보존한다. 테스트·lint·빌드를 통과한 변경만 모은다.
- 주간 공개 커밋을 직접 만들지 말고, 이력 확인 후 `node scripts/prepare-weekly-release.mjs --confirmed-no-published-release`로 준비한다. 이 명령은 월요일 09:00 KST 이후에만 동작하며 `.git/dfmoa-release-YYYY-MM-DD.lock`을 원자적으로 만들어 같은 체크아웃의 동시·반복 실행을 차단한다. 실패한 시도도 잠금을 유지하므로 임의 삭제·재시도하지 않는다.
- Netlify 검사에서는 마지막 빌드의 `CACHED_COMMIT_REF`를 확인하고 같은 커밋·같은 주 release의 재실행과 이전 주 release를 차단한다. 기록이 없거나 Git 이력을 확인할 수 없으면 공개를 보류한다. 별도 체크아웃·수동 hook 등 우회 경로까지 이 로컬 잠금이 보장하지 않으므로 공개 이력 확인 절차를 계속 유지한다.
- Netlify 공개 배포 이력에서 이번 한국 시간 주에 이미 정기 배포가 있었는지 확인한다. 이력을 확인할 수 없거나 이미 공개했으면 배포하지 않는다.
- 공개할 변경을 커밋할 때는 일반 변경 커밋에는 `[skip netlify]`를 붙인다. 검증 완료 후 해당 월요일 날짜를 사용한 `release(weekly): YYYY-MM-DD` 빈 커밋을 한 번만 push해 기존 Netlify Git 연결로 배포한다.
- `netlify.toml`의 ignore 검사에서 한국 시간 월요일·production·해당 주의 명시적 release 커밋만 허용한다. 일반 소스 커밋과 수집 커밋, 미리보기는 건너뛴다. `ignore`는 build hook을 막지 못하므로 기존 일일 hook 호출은 제거했다. 별도로 hook·수동 배포·CLI 배포를 실행하지 않는다.
- 재실행 시 같은 주 release 커밋과 Netlify 공개 이력을 확인한다. 실패한 공개를 임의 반복하지 않고 원인을 알린다. 긴급 추가 배포는 사용자 지시가 있을 때만 한다.
- 주간 정적 배포 사이 공개 가격·환율은 마지막 배포에 포함된 관측값이다. 실제 관측 날짜를 보존한다. 월간 혜택은 배포 전 행사 기간을 다시 검증하고, 사이트에 ‘실시간’ 또는 오늘 확인한 가격이라고 표시하지 않는다.

## 카테고리 확장

- `scripts/category-watchlist.mjs`에 10개 카테고리의 수집 후보와 목표를 관리한다. 전자기기·건강식품을 우선 확장하되 정확한 모델·구성이 검증된 가격만 채택한다.
- 전자기기 후보에 WF-1000XM5와 WH-CH720N, 건강식품에 메가맨 스포츠 180정을 추가했다. 에브리타임 로얄은 30포, 솔가 D3는 1000 IU 90정으로 구성을 명확히 했다. 기존 URL과 ID는 유지한다.
- `data/category-collection-review.json`에는 거절된 검색 결과의 제목·출처·실제 확인 시각만 기록해 다음 상품 규격 검토에 사용한다. 미확인 가격을 검증된 가격처럼 보관하거나 표시하지 않는다.
- 검증 가격이 있는 서로 다른 상품 3개 이상이면 기존 홈 규칙에 따라 카테고리가 활성화된다. 3개는 UI 기준이며 검색·광고 승인 조건이 아니다. 미확인 분야의 표시만 강제로 활성화하지 않는다.

## 2026-10-28 정확성 보강

- 본품/액세서리, 향수/샤워젤, 단품/묶음 및 브랜드를 구분한다. 새 원본 SKU는 `src/lib/verified-offer-identities.json`의 판매처 상품번호·브랜드·전체 제목·확인 시각으로 검증한다. 이 목록을 자동 검색 결과로 덮어쓰지 않는다.
- 패션·주얼리·식품에서 공식 SKU 1종씩 확인했다. 각 분야 3종 기준에는 아직 미달한다. 아이웨어·시계는 공식 공개 검색에서 검증 가능한 결과를 확보하지 못했으므로 준비 중을 유지한다.
- 일일 가격 이력은 확인된 원화만 기록하고 USD에 고정 환율을 곱하지 않는다. 각 판매처의 실제 관측 시각·상품번호·제목·출처 및 `exact-product-v2` 버전을 보존한다. 기존 버전 없는 이력은 검증된 새 이력으로 소급 표기하지 않는다.
- 화면은 관측 가격과 실제 결제 가격을 구분하고, 3일 이상 지난 값은 과거 관측 가격으로 표시한다. 시각은 KST로 통일한다. 주간 정적 가격을 현재 판매 가능한 Offer/AggregateOffer로 구조화하지 않으며 Product 기본 정보만 유지한다. 가격 리치 결과 자격보다 오해 없는 관측 정보 제공을 우선한다.
- 광고 진단은 각 광고 영역의 `data-ad-state`에 대기·제출·처리·충족/미충족·실패 상태를 기록한다. 외부 진단 전송이나 재요청을 추가하지 않는다. 로컬은 `preview-blocked`이며 광고 요청을 하지 않는다.
